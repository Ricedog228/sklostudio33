# SKLO.STUDIO — запуск по шагам

Подготовлен проект для Vercel: исходный дизайн сохранён, мобильное меню исправлено, обе формы подключены к серверному API. Публикация в вашем аккаунте, создание базы, подключение Telegram, домена и индексация ещё не выполнены.

## 1. Загрузка версии 1.2 — все файлы в одной папке

Эта версия специально рассчитана на загрузку всех файлов в корень GitHub. Никаких папок `scripts`, `api`, `lib`, `public` создавать не нужно. Необходимую структуру Vercel автоматически создаст команда `node build.mjs`.

1. Скачайте новый архив, распакуйте его на компьютере.
2. Откройте репозиторий GitHub и выберите ветку **main**.
3. Нажмите **Add file → Upload files**, выберите **все файлы из распакованного архива** и загрузите их в корень. Новые версии заменяют одноимённые файлы. Сам ZIP не загружайте.
4. Нажмите **Commit changes**. Сохраняйте изменения в **main**, новую ветку создавать не нужно.
5. Проверьте `package.json`: строка версии — `1.2.0`, команда build — `node build.mjs`. Если там осталось `node scripts/build.mjs`, загружена старая версия.
6. В Vercel откройте настройки существующего проекта:

| Настройка | Значение |
|---|---|
| Framework Preset | **Other** |
| Root Directory | Пустое поле — корень репозитория |
| Build Command | `npm run build` |
| Output Directory | **Выключить Override**; старое значение `dist` убрать |
| Install Command | По умолчанию, без Override |
| Node.js | **22.x** |
| Production Branch | **main** |

7. Запустите deployment **нового коммита** из main. Git-интеграция обычно запускает его автоматически после сохранения файлов. Если нажимаете Redeploy, выбирайте deployment нового коммита, а не старой версии; отключите старый Build Cache, если доступна такая опция.
8. В журнале должны появиться версия `sklo-studio@1.2.0`, команда `node build.mjs` и строка `Build Output API v3 ready — /api/lead, /api/status, /api/retry`.
9. Откройте сайт, затем `/api/status`. До подключения аккаунтов ожидается `{"enabled":false}` — это нормальный ответ работающей серверной функции с отключёнными заявками.

Если файлов не хватает, сборка выводит `Incomplete project upload. Missing: ...`. Догрузите перечисленные файлы в корень. Папки создаются только внутри результата сборки, автоматически.

До настройки формы отключены, индексация запрещена. `noindex` не является паролем. Если нужно ограничить доступ к тестовой версии, включите защиту развёртывания в Vercel.

Для коммерческого сайта нужен соответствующий тариф Vercel: Hobby предназначен для личного некоммерческого использования. Тариф выбирает владелец аккаунта.

## 2. Создать базу

1. Создайте проект в Supabase под аккаунтом владельца бизнеса. Сохраните пароль базы отдельно.
2. Откройте **SQL Editor → New query**.
3. Вставьте содержимое `setup.sql` и выполните один раз. Создадутся три таблицы и три серверные функции.
4. В настройках проекта скопируйте Project URL и серверный **secret key** (`sb_secret_...`). Ключ нужен только серверу. Публичный publishable/anon key здесь не подходит. Старый service_role JWT тоже поддержан.
5. В **Vercel → Project → Settings → Environment Variables** добавьте значения из таблицы ниже. Затем сделайте **Redeploy**.

| Переменная | Что поставить |
|---|---|
| `SUPABASE_URL` | Project URL Supabase, `https://…supabase.co` |
| `SUPABASE_SECRET_KEY` | Серверный secret key Supabase |
| `RATE_LIMIT_SALT` | Случайная строка минимум 32 байта |
| `TELEGRAM_BOT_TOKEN` | Токен собственного Telegram-бота |
| `TELEGRAM_CHAT_ID` | ID личного чата менеджера или группы для заявок |
| `CRON_SECRET` | Другая случайная строка минимум 32 байта |
| `ALLOWED_ORIGINS` | Точный адрес сайта без завершающего `/`, например `https://your-project.vercel.app`; несколько адресов — через запятую |
| `LEADS_ENABLED` | Пока `false`, затем `true` после настройки и проверки текста политики |
| `SITE_INDEXABLE` | Пока `false` |
| `PUBLIC_SITE_URL` | После покупки домена: `https://ваш-домен` |

Сгенерировать случайную строку на Mac: `openssl rand -hex 32`. Выполнить дважды для разных значений. Не добавляйте реальные ключи в HTML, GitHub, архив или переписку. Указывайте их в настройках окружения Vercel.

Ограничьте секреты нужным окружением Vercel. Для разработки лучше отдельная тестовая база и отдельный чат. При изменении переменных необходим новый deploy.

## 3. Подключить Telegram

1. В Telegram откройте официального **@BotFather**, выполните `/newbot`, задайте имя и username бота. Сохраните выданный токен в `TELEGRAM_BOT_TOKEN`.
2. Откройте своего бота и отправьте `/start`. Для группы добавьте туда бота и отправьте ему команду `/start@username_бота`.
3. Получите `message.chat.id` через Telegram Bot API `getUpdates`. Используйте локальный скрипт ниже, а не URL с токеном в истории браузера. Если бот уже обслуживается другой системой, создайте отдельного бота: не удаляйте существующий webhook.

```bash
python3 - <<'PY'
import getpass, json, urllib.request
secret = getpass.getpass('Bot token: ')
try:
    with urllib.request.urlopen('https://api.telegram.org/bot' + secret + '/getUpdates', timeout=15) as r:
        result = json.load(r)
    for update in result.get('result', []):
        message = update.get('message', {})
        chat = message.get('chat', {})
        if chat:
            print('Chat ID:', chat.get('id'), '|', chat.get('title') or chat.get('first_name'))
except Exception:
    print('Не удалось получить данные. Проверьте токен, сеть и наличие /start.')
PY
```

4. Выберите нужный ID, внесите его в `TELEGRAM_CHAT_ID` и сделайте Redeploy. Скрипт только читает обновления: он не отправляет сообщения.

## 4. Заполнить реальные сведения

В `index.html` замените «уточнюється перед запуском» на настоящий телефон, адрес и часы работы. Добавьте ссылки `tel:+380…` вместо кнопок «Зв’язатися», если нужен звонок одним нажатием. Цены сейчас «за запитом» — можно оставить так до утверждения прайса.

Подтвердите у владельца наличие выездного сервиса, OEM/OES, ADAS и перечисленных услуг автостудии. Эти услуги перенесены из исходника и не проверялись. Шаблонные отзывы удалены. Фото работ не добавлялись. Загрузка фото пока не реализована; обещания загрузки удалены из текста.

В `privacy.html` находится **черновик**, а не окончательный юридический документ. Укажите реального владельца данных, контакт для запросов, сроки хранения, порядок удаления и согласуйте обработку с фактическими условиями работы. После согласования удалите текст о черновике и маркер `DRAFT_POLICY`; при последующих изменениях обновите `consentVersion` в `core.js`. До этого не принимайте реальные заявки.

## 5. Включить и проверить заявки

1. После заполнения настроек и политики поставьте `LEADS_ENABLED=true`, сделайте Redeploy.
2. Откройте сайт и отправьте тестовую заявку с пометкой «ТЕСТ» и собственным телефоном. Это действие отправит сообщение в настроенный чат.
3. В **Supabase → Table Editor → sklo_leads** должна появиться строка с заявкой. Поля находятся внутри `payload`; `status` и `manager_note` можно менять вручную через защищённый кабинет Supabase.
4. Убедитесь, что сообщение пришло в нужный Telegram-чат, а у записи в `sklo_notifications` статус `sent`.
5. Проверьте обе формы, телефон, меню на мобильном и ошибку при отключённой сети. Заявка должна показываться принятой только после ответа сервера о сохранении.
6. Удалите тестовые заявки через Supabase после проверки. Связанные записи очереди удаляются автоматически.

### Если Telegram временно недоступен

Сначала в одной транзакции сохраняются заявка и задача уведомления. Затем сервер пытается отправить сообщение. При сбое задача остаётся в очереди. API `/api/retry` доступен только с заголовком `Authorization: Bearer <CRON_SECRET>`.

В `vercel.json` установлен резервный запуск раз в сутки в 08:00 UTC. Он обрабатывает до 20 задач за проход с ограничением по времени. Для рабочего бизнеса на подходящем тарифе замените расписание на `*/5 * * * *` — каждые 5 минут. Cron работает на production deployment Vercel. После смены расписания сделайте deploy и проверьте журнал запусков.

Доставка Telegram имеет семантику «как минимум один раз»: при обрыве после фактической отправки, но до фиксации результата возможен дубль уведомления. ID заявки позволяет его распознать. Сама заявка при повторе с тем же ключом не создаётся заново. После перезагрузки страницы новый запрос получает новый ключ и может создать отдельную заявку.

Проверяйте очередь `pending/sending` и журнал запусков при эксплуатации. Это небольшой стартовый backend, без отдельной панели мониторинга и CRM. Лимит — 5 новых заявок с одного IP за 15 минут; несколько людей за общим IP делят лимит. Honeypot и лимит уменьшают спам, но не заменяют дополнительную антибот-защиту при атаках.

## 6. Домен и Google — после проверки

1. Купите утверждённый домен на аккаунт владельца бизнеса.
2. В Vercel добавьте его через **Settings → Domains** и внесите у регистратора **именно те DNS-записи, которые покажет Vercel**. Не используйте случайные IP из чужих инструкций.
3. Дождитесь подтверждения домена и HTTPS. Выберите основной вариант адреса и настройте редирект второго варианта.
4. Обновите `ALLOWED_ORIGINS` и `PUBLIC_SITE_URL`. Уберите неиспользуемые тестовые адреса.
5. После утверждения контента и политики поставьте `SITE_INDEXABLE=true` и сделайте Redeploy. Сборка создаст `sitemap.xml`, canonical и `og:url`, откроет `robots.txt` и снимет `noindex` с главной. На Preview-окружениях Vercel индексация останется выключенной. Сборка намеренно не пропустит известные контактные заглушки и маркер черновика политики.
6. В Google Search Console подтвердите домен DNS-записью, отправьте `https://ваш-домен/sitemap.xml`, проверьте главную через URL Inspection. Дополнительно проверьте, что хостинг не добавляет `X-Robots-Tag: noindex` и production не закрыт авторизацией. Индексация и позиция в поиске не гарантируются.
7. Создайте Google Business Profile с реальными сведениями.

Метаданные description и Open Graph уже добавлены. Canonical и sitemap формируются только после указания реального домена. LocalBusiness JSON-LD, фотографию для превью, CRM, бухгалтерию, email-уведомления и рекламную аналитику нужно подключить отдельно после получения данных бизнеса и выбора сервисов.

Для будущего GTM подготовлено событие `generate_lead` после успешного сохранения. В него не передаются имя, телефон или VIN. Сам GTM/GA4 сейчас не подключён; при подключении потребуется обновить Content-Security-Policy и согласовать необходимые настройки согласия. UTM сохраняются в текущей странице, не в cookies; между визитами атрибуция не сохраняется.

## Локальный просмотр и структура

Установите Node.js 22 и выполните в папке проекта:

```bash
npm run dev
```

Откройте `http://localhost:3000`. Без `.env.local` сайт доступен для просмотра, но формы отключены. Для локальной проверки интеграций скопируйте `.env.example` в `.env.local` и заполните своими тестовыми настройками. Не размещайте этот файл в GitHub.

- `index.html` — страница, украинский текст и формы.
- `site.css` — исходный стиль и исправления адаптивности.
- `site.js` — меню и клиентская отправка.
- `lead.js` — серверный приём заявки.
- `status.js` — доступность настройки форм.
- `retry.js` — защищённый повтор уведомлений.
- `setup.sql` — база, очередь, ограничения доступа.
- `core.js`, `notifications.js` — проверки, Supabase и Telegram.
- `build.mjs` — сборка и переключение индексации.
- `api.test.mjs` — проверки сценариев API с имитацией внешних сервисов.

Команды проверки: `npm test` и `npm run build`. В `.vercel/output/static` попадают только HTML, CSS, клиентский JavaScript, favicon и robots из явного списка в build.mjs. Серверные функции с необходимыми модулями отдельно собираются в `.vercel/output/functions`. В собранном результате автоматически создаются пути api/ и lib/, необходимые импортам. Исходные lead.js, status.js и retry.js напрямую запускать не нужно: используйте npm run dev или Vercel. SQL, настройки окружения, инструкции и серверные файлы не публикуются как статические файлы. Папку `.vercel` генерирует сборка; загружать её на GitHub не нужно.

## Что проверено при подготовке версии 1.2

Прошли 11 автоматических проверок. Новая проверка собирает проект в чистой временной папке, загружает каждую собранную серверную функцию, проверяет ответы без настроенных аккаунтов и отсутствие серверных исходников в публичной части. Проверено также, что отсутствие `lead.js` вызывает понятную ошибку сборки. Проверялась именно загрузка всех исходных файлов в одну папку, без вложенных каталогов. Облачный deploy в аккаунте пользователя не выполнялся.


Автотесты проверяют валидацию, запрещённый origin, honeypot, слишком большой запрос, недоступность базы, повтор с тем же ID, ограничение частоты, успешную и неуспешную доставку Telegram, защиту retry. Внешние сервисы в этих тестах имитируются. Реальные Supabase, Telegram, Vercel и SQL-миграция требуют проверки в ваших аккаунтах после настройки. Проверены также HTML-якоря, уникальность ID, имена полей и сборка. Визуальная проверка в браузере не выполнена: установленный Playwright не имел браузера, загрузка браузера завершилась ошибкой. Перед запуском нужно проверить макет и обе формы на компьютере и телефоне.
