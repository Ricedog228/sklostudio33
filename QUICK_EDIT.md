# Быстрые изменения SKLO.STUDIO

## Установить это обновление

В обновление входят имя и тип стекла в форме, передача этих полей в базу и Telegram, а также раздел «Наші результати» вместо «Автостудія».

1. Распакуйте SKLO_STUDIO_project.zip.
2. Откройте https://github.com/Ricedog228/sklostudio33 и выберите main.
3. Add file → Upload files: перетащите все файлы из архива в корень репозитория, рядом с package.json. Замените одноимённые файлы одним коммитом. ZIP загружать не нужно.
4. Commit changes → Commit directly to the main branch → Commit changes (если ветка не защищена).
5. В Vercel → Deployments дождитесь Ready нового Production-деплоя с этим коммитом. При включённой Git-интеграции он запускается автоматически. Если не запускается, проверьте Settings → Git: нужный репозиторий и Production Branch main. Повторное развёртывание старого коммита новые файлы не добавит.
6. Откройте https://sklostudio33-gold.vercel.app и обновите страницу. Отправьте тестовую заявку с именем и типом стекла. В Telegram появится отдельная строка «Тип скла».

Переменные Vercel уже настроены — их менять не нужно. setup.sql повторно запускать не нужно. Новые поля хранятся в sklo_leads.payload. Старые заявки не изменяются.

## Быстро поменять текст, телефон или цену

Откройте index.html в GitHub → значок карандаша / Edit this file → найдите нужный текст → измените → Commit changes в main. Меняйте текст между HTML-тегами, сохраняя теги и атрибуты. При изменении номера телефона обновляйте и видимый номер, и ссылку tel:, если она есть. После Ready проверьте сайт.

Изменения в main при работающей интеграции сразу публикуются. Для крупного изменения можно создать отдельную ветку, проверить Preview в Vercel и затем объединить изменения в main.

## Добавить выполненную работу с фотографией

Пока фотографий нет, в разделе показано короткое сообщение о подготовке подборки. После первой записи оно заменится карточками автоматически.

1. Подготовьте реальную фотографию, желательно WebP или JPG около 1200–1600 пикселей по ширине, и назовите её work-01.jpg. Имена — латиницей в нижнем регистре, без пробелов. Поддерживаются jpg, jpeg, png, webp, avif.
2. В GitHub нажмите Add file → Upload files и загрузите фото в корень рядом с index.html. Папки создавать не нужно. Сохраните коммит.
3. Откройте results.json → карандаш. Вместо [] вставьте запись с настоящими данными работы:

```json
[
  {
    "title": "Марка и модель — выполненная работа",
    "description": "Краткое описание реальной работы на украинском языке.",
    "image": "work-01.jpg"
  }
]
```

4. Замените пример заголовка и описания своими данными, затем Commit changes в main. После Ready карточка появится на сайте. Порядок записей в файле определяет порядок карточек.
5. Для второй работы загрузите work-02.jpg и добавьте второй объект через запятую перед закрывающей ]. После последнего объекта запятой быть не должно. Имя image должно точно совпадать с загруженным файлом.

Чтобы заменить фотографию, загрузите новый файл с тем же именем. Чтобы убрать карточку, удалите её объект из results.json. Чтобы скрыть все карточки, верните []. В сборку попадают только фотографии, перечисленные в results.json; неиспользуемые фотографии не публикуются. Фотографии показываются в кадре 4:3 с обрезкой краёв — проверьте, что важная часть работы в центре.

## Что за что отвечает

| Файл | Что менять |
|---|---|
| index.html | Тексты, контакты, цены, структура страницы |
| results.json | Работы: заголовки, подписи, имена фотографий |
| work-01.jpg и другие work-* | Фотографии работ |
| site.css | Цвета, шрифты, размеры, расположение блоков |
| notifications.js | Состав сообщения Telegram |
| core.js | Проверки данных формы; обычные тексты сайта здесь не редактируются |

Токены и секретные ключи остаются только в Vercel Environment Variables. После изменения переменных нужен новый deployment. После изменения файлов при включённой Git-интеграции deployment запускается автоматически.
